`phase3_database_receipt.json` records before/after table counts, actual inserted
version UUIDs and content hashes, and an immediate idempotent rerun with zero

with a five-second lock timeout and compared SHA-256 multisets of every existing

may briefly block other writes; run ingestion in a maintenance window.

## Sources and applicability

`data/metadata/phase3_official_corpora_verified.json` binds PDF bytes, extracted
page text, official HTML snapshots and synthetic profiles by hash. RBI's live
official pages linked the same four queued PDFs. Each PDF was downloaded again
and matched its queued SHA-256 before candidate ingestion. A standalone
withdrawal marker blocks extraction. Absence of a marker and successful official
download do **not** prove legal currency or applicability.

The SEBI corpus preserves the official
[CSCRF circular of August 20, 2024](https://www.sebi.gov.in/legal/circulars/aug-2024/cybersecurity-and-cyber-resilience-framework-cscrf-for-sebi-regulated-entities-res-_85964.html),
[December 31, 2024 clarifications](https://www.sebi.gov.in/legal/circulars/dec-2024/clarifications-to-cybersecurity-and-cyber-resilience-framework-cscrf-for-sebi-regulated-entities-res-_90401.html),
and [August 28, 2025 technical clarifications](https://www.sebi.gov.in/legal/circulars/aug-2025/technical-clarifications-to-cybersecurity-and-cyber-resilience-framework-cscrf-for-sebi-regulated-entities-res-_96329.html).
These are selected instruments, not an exhaustive current consolidated rule
set. Other extensions, FAQs and amendments must be reviewed before legal use.

Every source has an explicit profile-bound pending applicability decision and
pending legal-current/amendment-completeness status. Neither entity has an
automatically approved current catalog. The fictional broker's CSCRF category
is deliberately unset pending threshold/category review. It is not a real
registered firm. RBI engineering scope is the existing fictional commercial
bank, not all bank categories.

`verify_corpus` rejects wrong profiles, foreign regulators, modified profile or
source artifacts, duplicate source versions, and attempts to promote pending
records through this ingestion path. `append_bank` accepts only the bank corpus.
SEBI blocks have exact page numbers and PDF-point bounding boxes, pending status
and official provenance; repeated exact blocks within a source are skipped.
Blocks can contain multiple requirements or contextual text. Their count is
not validated coverage. They are stored only in the receipt's separate
`sebi_review_packet`; no SEBI requirements or policies were inserted into the
shared bank database.

The current API remains single-bank and lacks tenant isolation. Offline profile
guards do not establish authenticated tenant isolation or enforce legal
applicability across legacy API paths. These sources are candidate catalogs;
their lexical policy matches do not establish compliance. Shared access and a
current applicability-aware assessment API remain pending isolation design and
tests. No real bank policies are uploaded or generated by this phase.

## Reproduction

Run from the project root, choosing new output paths on every run:

```powershell
uv run python -m regintel.foundation.expansion --output data/metadata/phase3_new_snapshot.json
uv run python scripts/ingest_phase3.py --output data/processed/validation/phase3_new_preflight.json
uv run python scripts/ingest_phase3.py --database --output data/processed/validation/phase3_new_receipt.json
uv run python -m regintel.foundation.cli inventory --database --output data/processed/validation/phase3_new_inventory.json
```

The ingestion script deliberately uses the checked-in verified registry, not a
new unreviewed download. A changed official PDF stops verification; preserve it
as another version and regenerate/review extraction before selecting it for
ingestion. Local preview UUIDs are reconciled to actual database version and
clause identities. Existing clause conflicts abort; reviewed obligation rows
are skipped rather than overwritten. No migration, reset, delete or historical
source promotion occurs. Serialized ingestion is required if calling the
low-level append function outside the supplied script.
